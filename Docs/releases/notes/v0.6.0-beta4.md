_Fourth beta of v0.6.0 — adds **per-style time formats** and hardens the timer time-parsing and dependency paths on top of `v0.6.0-beta3`._

### New

- **Per-style time formats.** Each style can now choose how its timers render the remaining time — applied consistently in the **mini views** *and* the main grid **Remaining** column:
  - **Classic** (default) — `1d 04:05:22` / `01:23:45` (unchanged from today).
  - **Long** — `1d 4:05:22` / `1:23:45` / `0:45` (collapses the leading unit, right-justified).
  - **Adaptive Compact** — `1d 4h` / `1h 23m` / `45s` (the two most-significant units).
  - **Full Compact** — `1d 4h 5m 22s` / `1h 23m 45s` / `45s`.

  Pick the format from the new **Time Format** column on the **Styles** tab; a live **Example** preview shows exactly what you will get. Existing tomes default every style to **Classic**, so nothing changes until you opt in.

### Fixes

- **Dependency delays are honored under every time format.** A dependent timer chain whose style used a compact format (e.g. Spawn = Full Compact `9m 30s`) could fire the entire chain at once, because the delay was read from the display string with a parser that only understood `HH:MM:SS`. The dependency check now reads the timer's authoritative elapsed milliseconds, and the parser understands every display format.
- **Mini-view warnings are format-independent.** Warning colors are driven by the timer's raw remaining milliseconds rather than by re-parsing the displayed text, so compact formats like `1d 4h` or `45s` no longer trigger false warnings.
- **Lossless timer-state persistence.** Saved remaining times are normalized to the canonical `HH:MM:SS` form at the storage boundary (compact formats are lossy by nature), so timer state round-trips exactly across restarts regardless of the chosen display format.

### Under the hood

- **Timer-maintenance logic extracted from `FormMain`** into a dedicated `TimersController` (Add / Duplicate / Chain, duration validation + shorthand auto-format, and grid CRUD), continuing the Controller / Repository pattern already used by the Styles, Views, Categories, and Characters tabs.
- **Grid layouts survive new columns.** Adding the Styles "Time Format" column no longer pushes a saved grid layout past its edge — newly-added columns are now fitted into the existing footprint instead of overflowing it.

### Upgrade notes

> ⚠️ **Back up your `.tdb` tome before upgrading.** This beta adds one new column (`styles.TimeFormat`) through an idempotent, one-shot migration — your existing styles, views, timers, colors, and saved column widths are all preserved, and every style defaults to the **Classic** format so timers render exactly as they do today. Includes all fixes from `v0.6.0-beta3`.
